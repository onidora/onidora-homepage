# 計画フロー

リポジトリルートの `AGENTS.md` と `plan/README.md` を読む。計画と実施記録はGitで共有する。既存workに該当する作業は新規作成せず更新する。

## workの単位と構成

- 独立して実装・検証できる成果で分ける。準備・調査・レビューだけのworkに分断しない。
- 計画の起点は `plan/work/YYYY-MM-DD-内容名.md`。日付は作成日、内容名は日本語で記す。
- 章は「目的と概要 → 構成 → 完了条件 → 方針と手順 → 着手条件（要確認） → 実施記録」の順。構成には対象ファイル、完了条件には具体的な検証を含める。
- 未確定事項は着手条件にまとめ、何の作業がその判断に依存するかを書く。計画作成のみの依頼を実装許可にしない。
- 小さな修正は直接実施してよい。多くのworkに共通する規則はAGENTS.mdを参照し、本文を複製しない。

## 実行と記録

- ユーザーがすでに許可した範囲は実装へ進める。対象外の後続workへ自動で進まない。
- 途中経過と再開に必要な事実は実施記録に日付付きで追記する。判断が決まったら着手条件を更新する。
- 実施記録に変更、実際の検証結果、計画との差分、残課題を残す。
- 完了条件を満たしたworkは `plan/work/archive/` へ移し、参照リンクを更新する。ユーザー確認が完了条件ならその回答を待つ。
- 進行状態の正は置き場所と実施記録。別のstatusフィールドや進捗一覧を重複管理しない。

## proposal

今は実装に落とさない検討事項をユーザーに求められた場合だけ `plan/proposal/` を作る。「背景・目的／検討事項／メモ」の3章で、設計と手順はworkに持たせる。検討が決着したら `proposal/archive/` へ移す。必要になるまで空フォルダは作らない。

GitHubへの作成・push、公開の許可はAGENTS.mdに従う。workは操作権限を追加しない。
