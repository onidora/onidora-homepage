## 採否と理由

| 項目 | このサイトでの扱い | 理由 |
| --- | --- | --- |
| AGENTS.mdを共通入口にする | 採用 | ツール間で指示を重複させない |
| workから始め、proposalは必要時だけ | 採用 | 単純な追加作業を二段階の文書にしない |
| 成果単位で分割し、調査だけを分離しない | 採用 | 1本のworkで再開・完了判定できる |
| 状態は置き場所、経過は実施記録 | 採用 | statusや台帳の二重管理を防ぐ |
| 日本語の内容名・日付、archiveへの移動 | 採用 | 既存の読み方を継続できる |
| ローカル専用の計画・スキル | 変更: `plan/` と `.agents/skills/` をGit共有 | GitHubを通じて別エージェントに引き継ぐため |
| スキル本文とClaude用トリガーの二層構成 | 変更: SKILL.mdを唯一の正本にする | この規模ではポインタ層が不要。AGENTS.mdからも参照する |
| workの必須10章 | 変更: 6章に統合 | 目的・構成・完了条件は先頭に保ち、手順・検証・記録を短くする |
| 毎workで承認・実機確認を必須にする | 変更: 既に依頼された範囲は進め、必要な確認だけを着手条件にする | 今回はローカル実装が許可済み。未実施の確認を完了扱いにはしない |
| コミット・pushを原則禁止 | 変更: ローカルコミット可、GitHub作成・pushはユーザー確認後 | 今回のGitHub登録依頼に合わせる |
| 生成物を直接編集しない・型検証・根拠付き報告 | 採用 | Astroでも保守性・再現性に有用 |
| Biome、モノレポ、ゲームのchecker/test_all | 不採用 | Astro check/buildを基本にし、依存と運用を小さくする |
| RPGツクール、プラグイン登録、prototype、ゲームUI、単一ガード、全メソッド削除確認 | 不採用 | ゲーム固有の実装・検証手順 |
| 試作ブランチ専用archive_protとモデル別役割分担 | 不採用 | 小規模サイトで必要ない |

元の `agent/local/` には個人的な内容もあるため、既存の計画本文・メモ・履歴は移植していない。
